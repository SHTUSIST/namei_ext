# sandboxfs 0.2.0 Protocol Audit

Date: 2026-07-28

## Motivation

The Build Action RQ2 experiment uses official sandboxfs as its only main
baseline. This audit reads the exact source selected by the frozen plan so the
experiment uses the real lifecycle and does not accidentally weaken or
handicap the baseline.

## Process Lifecycle

The baseline process remains in the foreground. The controller owns its stdin,
stdout, and process lifetime:

```text
sandboxfs --input=- --output=- --reconfig_threads=1 --ttl=0s MOUNTPOINT
```

`--reconfig_threads=1` gives deterministic acknowledgement ordering.
`--ttl=0s` prevents a long configured metadata TTL from spanning lifecycle
samples. The experiment must not enable `--node_cache`; the official option
description marks it as known broken.

Readiness requires all of the following:

1. the process is live;
2. `findmnt` identifies the mount as sandboxfs/FUSE;
3. one real `CreateSandbox` request receives a matching acknowledgement with a
   null error; and
4. a mapped file can be resolved, enumerated, and read.

## Reconfiguration Protocol

The input is a stream of JSON requests. A positive mapping uses prefix zero for
absolute paths:

```json
{
  "CreateSandbox": {
    "id": "action-a-s001",
    "mappings": [
      {
        "path_prefix": 0,
        "path": "/input-000001.txt",
        "underlying_path_prefix": 0,
        "underlying_path": "/lower/action-a/input-000001.txt",
        "writable": true
      }
    ],
    "prefixes": {}
  }
}
```

A successful response is:

```json
{"id":"action-a-s001","error":null}
```

Destroy uses:

```json
{"DestroySandbox":"action-a-s001"}
```

The controller must check both response ID and null error. A parseable response
with an error is a hard failure.

## Fairness Decision

Mappings use `writable:true`. This does not make the action write its inputs.
It prevents sandboxfs from adding an extra read-only policy that `namei_ext`
does not impose. Both conditions then delegate access to the same lower object
mode, UID, and GID. The generated Bazel action remains byte-identical and
read-only in both conditions.

Mapping the lower root wholesale is invalid because undeclared files would be
visible. Each action therefore receives exactly one positive mapping per
declared input and no information about undeclared or post-setup unknown
names.

## Sample Isolation

sandboxfs exposes `CreateSandbox` and `DestroySandbox` but no reset operation.
Every action in every lifecycle sample must therefore use a unique sandbox ID.
After a sample:

1. send Destroy for both IDs;
2. wait for matching successful acknowledgements;
3. verify old IDs are absent through lookup and directory enumeration; and
4. only then begin the next sample.

For final shutdown, destroy all live IDs, close stdin, unmount with
`fusermount -u`, and wait for a zero daemon exit. SIGTERM is reserved for
failure cleanup and is not a successful lifecycle.

## View Placement

Two sandbox IDs coexist under one mount. Each Bazel action must receive a
private mount namespace and bind its own `/MOUNTPOINT/ID` view onto the same
absolute logical action path used by the `namei_ext` condition. This keeps the
BUILD file, command, path strings, and action concurrency barrier identical.

The feasibility of this private-namespace bind is a real KVM preflight gate,
not established by this source audit.

## Remaining Risks

- The KVM guest currently runs experiment processes as root. The preflight must
  verify that sandboxfs's default self-access mode works when daemon and action
  share that UID; do not switch to `--allow=root`, which the Linux source path
  rejects as broken.
- A zero TTL and unique IDs reduce cache carryover but do not prove the private
  bind-mount protocol works in virtme-ng. That is part of the paired real
  preflight.
- Toolchain and libfuse identities must be captured in the formal result
  artifacts; the local inspection binary is not itself a formal artifact.

## 2026-08-07 RQ2 Re-entry Correction

The reviewed re-entry plan in
`docs/tmp/2026-08-07-build-action-rq2-reentry-plan.md` supersedes two harness
requirements above for the main comparison:

- sandboxfs now uses its upstream default 60-second metadata TTL; and
- destroy completion requires the official matching acknowledgement and final
  unmount, but not immediate post-destroy lookup or readdir disappearance.

Unique sandbox IDs prevent cross-sample reuse, and the Bazel action does not
access a destroyed ID. Immediate disappearance before the official TTL expires
is therefore not part of the workload oracle. Requiring it forced metadata
caching off and could disadvantage sandboxfs on the measured action path.

The mapping format, writable-mode fairness decision, unique-ID rule,
acknowledgement checks, private view placement, and clean daemon shutdown remain
in force. Artifact versions and source commits remain recorded; checksum
manifests and checksum gates are not experiment evidence and are no longer
executed by this path.
